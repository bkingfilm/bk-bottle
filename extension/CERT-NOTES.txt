v0.2.2: two changes since 0.2.0. (1) The panel gains a Previous/Next control to revisit recently fished bottles (stored locally). (2) Bug fix: on Bilibili the button is now injected only after the page finishes its own rendering; injecting earlier could interfere with Bilibili page layout on slow machines. No permission change.

BK Bottle lets people anonymously exchange videos they are watching and games they are playing. Users put links into a "bottle", throw it into the sea, and get a random stranger's bottle back. No account, no sign-in, no messaging, no ads.

HOW TO TEST (no test account needed; UI is Chinese):

1. Click the toolbar icon: the panel fetches one random bottle (YouTube/Bilibili/Steam cards). "再捞一个" = fish another, "收藏" = save/upvote.
2. On any YouTube watch page, Bilibili video page or Steam store game page, one button "装进瓶子" (= add to bottle) appears near the title/like row and adds that item to the queue.
3. On a public Steam community profile (e.g. steamcommunity.com/id/st4ck), "把最近在玩的装进瓶子" (= bottle my recent games) appears above the Recent Activity block and adds the 2-4 games shown there.
4. In the panel "扔进海里" (= throw) submits the queue as a new bottle; with an empty queue it reads "去网页扔一瓶" and just opens our site.

PERMISSIONS

storage: anonymous local id + the not-yet-thrown queue, kept on the user's machine.

https://b.bking.film/*: our own backend (fetch/throw bottles, receipts).

youtube.com, bilibili.com/video, store.steampowered.com/app, steamcommunity.com/id + /profiles: only to inject that one button and, at the moment the user clicks it, read the current page's public metadata (video/app id, title; Bilibili thumbnails must be read client-side because Bilibili blocks datacenter IPs). Steam titles and covers are re-fetched server-side from Steam's public appdetails API, so the extension uploads only app ids. No Steam login is read or required.

No history access (permission not requested). No new tab, homepage or search override. No remote code, no eval.
